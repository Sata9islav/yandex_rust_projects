# Streaming Quotes

Проект на Rust для передачи биржевых котировок.

Сервер принимает TCP-команду подписки, после чего отправляет котировки клиенту по UDP. Клиент периодически отправляет UDP-сообщения `PING`, чтобы сервер понимал, что подписка всё ещё активна.

## Возможности

- TCP-команда подписки `STREAM`
- передача котировок по UDP
- фильтрация котировок по тикерам клиента
- отдельный поток генерации котировок
- отдельный UDP-поток для каждого клиента
- keep-alive через `PING`
- остановка стрима при превышении тайм-аута
- чтение списка тикеров из файла
- обработка ошибок через `Result`
- юнит-тесты для протокола, котировок, фильтрации и чтения тикеров

## Файл доступных тикеров

Сервер читает доступные тикеры из файла:

```text
assets/tickers.txt
```

Пример содержимого:

```text
AAPL
MSFT
TSLA
GOOG
AMZN
```

Каждый тикер должен находиться на отдельной строке. Пустые строки пропускаются, пробелы в начале и конце удаляются.

## Запуск сервера

Из корня проекта:

```bash
cargo run --bin server
```

По умолчанию TCP-сервер слушает адрес:

```text
127.0.0.1:7878
```

Ожидаемый вывод:

```text
Server listening on 127.0.0.1:7878
```

## Запуск клиента

В отдельном терминале:

```bash
cargo run --bin client -- 127.0.0.1:7878 9000 assets/tickers.txt
```

Формат запуска:

```text
cargo run --bin client -- <tcp_server_address> <local_udp_port> <tickers_file>
```

Аргументы:

- `127.0.0.1:7878` — TCP-адрес сервера;
- `9000` — локальный UDP-порт клиента;
- `assets/tickers.txt` — путь к файлу тикеров клиента.

Для второго клиента нужно выбрать другой UDP-порт:

```bash
cargo run --bin client -- 127.0.0.1:7878 9001 assets/tickers.txt
```

## TCP-протокол

После подключения сервер отправляет приветствие:

```text
Welcome to Streaming
```

Клиент отправляет команду:

```text
STREAM <udp_addr> <tickers>
```

Пример:

```text
STREAM 127.0.0.1:9000 AAPL,MSFT,TSLA
```

При успешной подписке сервер отвечает:

```text
OK
```

При ошибке сервер отвечает:

```text
ERR <описание ошибки>
```

Примеры:

```text
ERR invalid command: WRONG
ERR invalid UDP address: invalid-address
ERR empty ticker list: ticker list is empty
ERR unknown ticker: UNKNOWN
```

## UDP-протокол

Формат одной котировки:

```text
ticker|price|volume|timestamp_ms
```

Каждая котировка заканчивается символом новой строки `\n`.

Пример:

```text
AAPL|201.42|3500|1785530000000
```

Поля:

- `ticker` — тикер инструмента;
- `price` — цена типа `f64`;
- `volume` — объём типа `u64`;
- `timestamp_ms` — Unix timestamp в миллисекундах типа `u64`.

## Keep-alive

Клиент примерно каждые две секунды отправляет серверу UDP-датаграмму:

```text
PING
```

Сервер удаляет пробелы и перенос строки через `trim()` и проверяет сообщение. При получении `PING` сервер обновляет время последней активности подписки.

Если `PING` не приходит дольше установленного тайм-аута, сервер:

1. останавливает отправку котировок;
2. завершает UDP-поток клиента;
3. удаляет неактивную подписку после закрытия канала.

## Архитектура

```text
общий генератор
        |
        v
список каналов клиентов
        |
        v
отдельный Receiver клиента
        |
        v
фильтр тикеров клиента
        |
        v
UDP-адрес клиента
```

Для каждого клиента создаётся отдельный канал:

```rust
mpsc::channel::<StockQuote>()
```

Общий генератор отправляет копию котировки всем активным клиентам.

UDP-поток клиента проверяет тикер:

```rust
if !ticker_filter.contains(&quote.ticker) {
    continue;
}
```

Если тикер отсутствует в подписке, котировка пропускается.

## Остановка клиента

Клиент и сервер корректно завершают связанные потоки в следующих случаях:

- TCP-соединение закрыто;
- канал котировок закрыт;
- произошла сетевая ошибка;
- превышен тайм-аут `PING`.
